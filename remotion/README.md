# Dockentra motion — Remotion

Основной движок видео Dockentra. Каждая сцена — React-компонент Remotion.
Стек прежний: Node + headless Chromium + ffmpeg (ffmpeg встроен в Remotion).

- **Remotion 4.0.529** — композиции, `useCurrentFrame`, `interpolate` / `Easing`, `<Sequence>`, рендер.
- **GSAP 3.15** — траектории иконок: дуги (у x и y разные ease), overshoot 1.05→1.0, `elastic.out`,
  падение. Таймлайн создаётся `paused` и на каждом кадре переводится в `frame / fps` через `seek`,
  поэтому кадры детерминированы и одинаковы во всех воркерах рендера.
- **Lottie:** `lottie-react` поставлен по запросу. Внутри композиций нужно использовать `@remotion/lottie`:
  он синхронизирует Lottie с кадром. `lottie-react` проигрывает анимацию в реальном времени, и при рендере
  кадры выйдут рваными.

## Команды

```bash
npm ci
npm run fonts     # скачать Manrope / Inter / IBM Plex Mono с Google Fonts CDN в public/fonts
npm run music     # синтезировать оба трека + акценты, −17 LUFS (нужны numpy и imageio-ffmpeg)
npm run studio    # живой превью-редактор
npm run render:creator          # 29.09 «Creator samples» → out/dockentra-creator-samples-2909.mp4
npm run render:creator-frozen   # тот же ролик с замороженной камерой (для приёмки)
npm run check:creator           # чек-лист dockentra-motion по обоим рендерам
npm run render                  # 28.09 «Same order, three ways»
npm run check
npm run smoke     # минимальный пример HelloDockentra
```

Chromium для рендера — локальный (`remotion.config.ts`, по умолчанию headless shell из
`/opt/pw-browsers`; переопределяется через `REMOTION_BROWSER_EXECUTABLE`), чтобы Remotion не скачивал свой.
Шрифты завендорены в `public/fonts`, потому что браузер Remotion во время рендера не ходит в сеть. Источник —
Google Fonts CDN, URL каждого файла записан в `public/fonts/manifest.json`.

## Приёмка «Same order, three ways» (`npm run check`)

```
[PASS] Hard rule: no frame unchanged > 1 s          — самый длинный стоп 0.37 s (пауза на 27 s по сценарию)
[PASS] 1. Motion visible in every segment           — движение в 70–100 % кадров каждого сегмента
[PASS] 2. 5 random timecodes: >= 4/5 mid-animation  — 5/5; по всем кадрам 93 %
[PASS] 3. Pattern interrupt                         — жёсткая склейка 20.00 s (удар коробки + тряска), раскрытие финала 34.40 s
[PASS] 4. More than one easing profile              — 13 профилей
[PASS] 5. Palette and logo                          — только 5 цветов бренда; логотип 600 мс @ 34.5 s, на экране последние 1.5 s
[PASS] Prohibited: text motionless > 2 s            — максимум 1.33 s
[PASS] Subtitles not mint, >= 240 px from bottom    — 320 px, 0 мятных пикселей
```

Пункты 1–2 в скрипте проверяются по пикселям. Он считает, где меняется передний план (текст, иконки, субтитры),
и дрейф фона не засчитывает как движение. Просмотр на 0.25x человеком это не заменяет.

## 29.09 «Creator samples» — v2, 38 с

Первая версия провалилась: красиво двигалась, но было непонятно, о чём ролик. v2 собрана с нуля вокруг одной метафоры:
сетка из 20 кружков-криейторов (`@creator_01…20`) и календарь Пн–Пт над ней. Кружок горит мятным с ▶, когда
криейтор получил сэмпл и выложил видео, и гаснет в серый с ×, когда сэмпл не дошёл.

- `src/creator/script.json` — весь текст на экране и голос. Это единственный источник: его читают и композиция, и чек-лист.
- `src/creator/timeline.ts` — сюжетные точки `T`, кто загорается и когда, все траектории на одном GSAP-таймлайне.
- `src/creator/CreatorSamples.tsx` — фон, календарь, кружки, подписанная стопка «SAMPLES SENT», куча, финал.

Мятный — только у горящих кружков, поэтому фон тёмный (Dock Ink), а текст белый. Сходится счёт:
4 кружка к среде, ещё 2 в пятницу = 6 вышло, 14 сорвалось.

### Приёмка (`npm run check:creator`) — 10/10 автоматических проверок + ручной пункт 6

Движение проверяется на финальном рендере и на рендере с замороженной камерой. Пункт 7 и правила про текст
считаются по `script.json`: ≤ 7 крупных слов одновременно, время на чтение, субтитр не повторяет заголовок.
Для пункта 6 скрипт вырезает кадры 0:08 / 0:20 / 0:33; оценивает их человек.

## Тур по складу — 28 с, изометрия (`WarehouseTour`)

Одно помещение на весь ролик, камера едет от станции к станции: приёмка → сообщение бренду → хранение →
сборка и упаковка → отправка → общий план. Утверждённые ключевые кадры лежат в `out/warehouse-keyframes/`.

- `src/warehouse/iso.tsx` — изометрия 30°, коробки, цилиндры, подписи на гранях, перчатка.
- `src/warehouse/Room.tsx` — помещение: стеллаж A1–A6, стол приёмки с камерой на штативе, стол упаковки
  (скотч, весы, принтер этикеток, мейлеры), клетка у роллетной двери DISPATCH, паллет.
- `src/warehouse/timeline.ts` — путь камеры (GSAP) и состояние склада в каждый момент: коробка, 12 банок,
  рука, мейлер, клетка.
- `src/warehouse/script.json` — заголовки, субтитры, текст голоса. Его читает и чек-лист.

`npm run render:warehouse` и `npm run check:warehouse` → 9/9 автоматических проверок; кадры 0:07 / 0:14 / 0:19 / 0:23 / 0:27
вырезаются для ручной проверки.

Правки v2: рук нет — предметы двигаются сами; камера на штанге видна целиком, объективом вниз над рядами,
вспышка — локальный конус на 0,3 с (+ короткий толчок камеры как единственный резкий акцент); брак (2 банки)
после фото уходит в короб «DAMAGED · ON HOLD», который потом стоит на нижней полке A4; на полку A2 уходят
только целые (A2 · 118 units); в сцене хранения стол приёмки и штатив растворяются; этикетка выходит из принтера
и ложится на мейлер на весах; субтитры 46 px по фразам голоса; финал — логотип 40 % ширины по центру, цена
и адрес под ним, склад за ними 30 % и размыт. Мятный — только брак (кольца, ярлыки DAMAGED).
