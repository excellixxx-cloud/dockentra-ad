# Dockentra — Motion Design Skill

## Проблема, которую этот скилл решает
Первая попытка сгенерировать ролик дала слайд-шоу: текст на сплошном фоне, смена карточек через fade. Это НЕ считается видео с движением. Каждый новый билд проверяется на этот же провал.

## Жёсткое правило приёмки
Ни один кадр не может оставаться визуально неизменным дольше 1 секунды. Если поставить видео на паузу в случайный момент — на экране должен быть виден элемент в процессе движения (масштабируется, сдвигается, деформируется, заполняется), а не статичная композиция, ждущая смены.

## Библиотека допустимых движений
- **Кинетическая типографика**: слова появляются по одному (stagger 60–90ms между словами), не весь блок текста разом. Easing — никогда linear, только `cubic-bezier(.22,1,.36,1)` (замедление в конце) для появления, `cubic-bezier(.4,0,.2,1)` для перемещения.
- **Иконки/объекты**: движение по дуге или с лёгким overshoot (scale 1.05 → 1.0), никогда просто opacity 0→1 на месте.
- **Pattern interrupt**: минимум один резкий монтажный акцент за ролик — падение объекта, звук, мгновенная смена ритма после плавного участка. Заимствовано из сценариев Dockentra Overhead — так удерживают досмотр.
- **Параллакс/глубина**: фон и передний план двигаются с разной скоростью, даже на 5–10%, — создаёт ощущение трёхмерности без 3D-рендера.
- **Continuous motion между сценами**: элемент предыдущей сцены не исчезает, а трансформируется в элемент следующей (morph/shared element transition), если это возможно логически.

## Что запрещено (сигнал халтуры)
- Fade-in/fade-out как единственный тип перехода.
- Текст, неподвижно стоящий на экране дольше 2 секунд.
- Статичный однотонный фон без единого движущегося элемента.
- Одинаковый easing на каждой анимации ролика (читается как шаблон, не как дизайн).

## Технический стек по умолчанию
HTML/CSS/JS сцена → рендер через Playwright + headless Chromium → покадровый захват или запись экрана → кодирование в mp4 через ffmpeg. Шрифты — Google Fonts CDN (Manrope, Inter, IBM Plex Mono). Анимация — CSS transitions/keyframes или Web Animations API; для сложных траекторий допустим GSAP (подключить через CDN).

## Бренд-констрейнты (Dockentra Brand Book v2.0 — не переопределяются этим скиллом)
- Цвета: Dock Ink #0B0D10, Mint #4FDCA9, Dock Green #0F5F4A, Bay Grey #F5F7F8, White. Один мятный акцент на композицию.
- Иконки: 2px stroke, скруглённые углы, без стоковых изображений и фото (их не существует).
- Логотип: только диагональная заливка снизу-вверх, 600ms, `cubic-bezier(.22,1,.36,1)`, без bounce, в последнем кадре 1.5 сек.
- Субтитры: не мятным цветом, не ниже 240px от нижнего края кадра.

## Чек-лист перед выдачей готового mp4
1. Просмотреть видео на скорости 0.25x — движение видно в каждом сегменте?
2. Поставить на паузу в 5 случайных таймкодах — хотя бы в 4 из 5 виден элемент в процессе анимации?
3. Есть ли хотя бы один pattern interrupt на весь ролик?
4. Использован ли более чем один easing-профиль?
5. Соответствует ли цветовая палитра и логотип брендбуку?

Если хотя бы один пункт не проходит — переделать сцену, не публиковать.
